# HU-052: Validar que Router.Route() elige proveedor correcto

## Resumen
Router debe elegir el proveedor correcto según capability requerida. Necesario verificar y loguear la decisión.

## Descripción Técnica

Como **usuario** quiero **que el Router elija automáticamente el mejor proveedor según capability** para que **no tenga que especificar proveedor en cada request**.

## Acceptance Criteria

```gherkin
Given: config.yaml con 5 proveedores (openai, anthropic, local, google, aihubmix)
When: POST /v1/chat/completions
Then: Router.Route("chat") retorna proveedor disponible
And: proveedor tiene adapter inicializado
And: logs muestran: "routing: capability=chat, chosen_provider=openai, quality_score=95"

And: si capability "reasoning" solicitada
  Then: Router retorna anthropic o openai (solo ellos support reasoning)
  And: google/local/aihubmix no pueden ser elegidos

And: si proveedor #1 cae (circuit breaker)
  Then: Router retorna siguiente en cadena
  And: logs muestran fallback: "fallback: openai circuit_open, trying anthropic"
```

## Investigación Requerida

1. **Revisar router.Route()**
   - ¿Retorna provider name o provider object?
   - ¿Valida que proveedor tiene adapter?
   - ¿Valida que modelo existe en proveedor?

2. **Revisar registry**
   - ¿Está parseando config.yaml correctamente?
   - ¿Está validando que cada proveedor en routing tiene adapter?

3. **Revisar failover**
   - ¿Está respetando el orden de proveedores en config.yaml?
   - ¿Está tracking circuit breaker state por proveedor?

## Implementación

### Logging en router.go
```go
// router.go, método Route()
log.Printf("routing: capability=%s, providers_available=%v", capability, availableProviders)

for _, provider := range providers {
  if !r.registry.IsAvailable(provider) {
    log.Printf("  %s: unavailable (no adapter)", provider)
    continue
  }
  
  p := r.registry.Provider(provider)
  log.Printf("  %s: quality=%d, latency_p50=%dms", provider, p.QualityScore, p.LatencyP50)
  
  return provider, nil
}

log.Printf("routing FAILED: no provider available for %s", capability)
return "", ErrNoProvider
```

### Testing
```bash
# Ver routing decision
curl -v http://localhost:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-4o","messages":[{"role":"user","content":"test"}]}'

docker logs api-llm-gateway | grep routing
# Esperado: routing: capability=chat, chosen_provider=openai
```

## Criterio Pase
- ✓ Logs muestran decisión de routing
- ✓ Provider elegido tiene adapter
- ✓ Request llega al adapter correcto
- ✓ Failover respeta orden en config.yaml
- ✓ No hay "sin adapter para proveedor" warnings

## Bloqueos Conocidos
- Si no hay adapters construidos → Router no puede elegir ninguno
- Fix: Asegurar buildAdapters() crea adapters para todos los proveedores en config.yaml
