# HU-051: Debuguear y fijar GatewayProcessor.ProcessChat()

## Resumen
ProcessChat() llama a failover.Complete() que devuelve error. Necesario investigar por qué falla y fixear.

## Descripción Técnica

Como **usuario** quiero **que POST /v1/chat/completions devuelva 200 con respuesta válida** para que **pueda usar el Gateway para chat**.

## Acceptance Criteria

```gherkin
Given: request válido POST /v1/chat/completions
  model: "gpt-4o"
  messages: [{"role":"user","content":"test"}]
When: envío request
Then: HTTP 200
And: response.choices[0].message.content es string no vacío
And: logs muestran proveedor utilizado
And: latencia < 5s

And: si falla API key, devuelvo HTTP 401 (no 500)
And: si no hay provider, devuelvo HTTP 503 (no 500)
And: si timeout, devuelvo HTTP 504 (no 500)
```

## Investigación Requerida

1. **Revisar failover.Complete()**
   - ¿Qué devuelve cuando no hay adapters?
   - ¿Qué devuelve cuando falla el adapter?
   - ¿Está retornando error nil cuando debería?

2. **Revisar Router.Route()**
   - ¿Retorna proveedor válido?
   - ¿Hay validación de que el modelo existe?

3. **Revisar adapter.Adapter interface**
   - ¿Qué error types esperamos?
   - ¿Cómo differenciamos entre temporal vs permanent failures?

## Implementación

### Debug Steps
```go
// En processor.go, añadir después de failover.Complete()
if err != nil {
  log.Printf("failover.Complete failed: %#v", err)  // print full struct
  
  // Inspect error type
  switch err.(type) {
  case *adapter.ProviderError:
    log.Printf("ProviderError: %v", err.(*adapter.ProviderError))
  default:
    log.Printf("Other error: %T", err)
  }
}
```

### Fix (probable)
Si failover devuelve nil cuando todos los adapters fallan, necesario:
- Validar que al menos 1 adapter está disponible
- Retornar error específico si ninguno disponible
- Que handler traduzca error a HTTP status correcto

## Testing

### Happy Path
```bash
# Con OpenAI API key válida
curl -X POST http://localhost:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-4o","messages":[{"role":"user","content":"test"}]}'
  
# Esperado: HTTP 200 + choice con content
```

### Error Cases
```bash
# Sin adapters
docker-compose down && docker-compose up -d
# Esperado: HTTP 503

# Con API key inválida (actualizar .env)
# Esperado: HTTP 401
```
