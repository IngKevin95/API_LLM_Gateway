# HU-050: Añadir logging estructurado al OpenAI handler

## Resumen
El handler `/v1/chat/completions` devuelve HTTP 500 sin visibilidad sobre qué falló internamente. Necesario instrumentar con logging para debuguear.

## Descripción Técnica

Como **desarrollador** quiero **ver logs detallados de qué sucede en cada paso del handler** para que **pueda debuguear errores HTTP 500 rápidamente**.

## Acceptance Criteria

```gherkin
Given: Handler OpenAI ProcessChat está instrumentado
When: llamo POST /v1/chat/completions
Then: logs muestran:
  - modelo solicitado
  - número de mensajes
  - proveedor elegido por Router
  - latencia en ms
  - contenido de respuesta (primeros 50 chars)
  
And: si hay error, logs muestran stack trace completo
And: logs están en formato JSON (key=value)
```

## Implementación

### Archivos a Modificar
- `src/cmd/gateway/processor.go` — ProcessChat()
- `src/internal/api/openai/handler.go` — HandleChatCompletions()

### Líneas de Código
```go
// processor.go ProcessChat()
log.Printf("ProcessChat: model=%s, messages=%d, capability=%s", req.Model, len(req.Messages), "chat")

// Después de failover.Complete()
if err != nil {
  log.Printf("ProcessChat ERROR: %v (type: %T, provider: %v)", err, err, req.Model)
  return nil, err
}

log.Printf("ProcessChat OK: content_len=%d, latency_ms=%d", len(resp.Content), elapsed)
```

## Testing

### Manual
```bash
curl -X POST http://localhost:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-4o","messages":[{"role":"user","content":"test"}]}'

# Ver logs
docker logs api-llm-gateway -f
```

### Criterio Pase
- Logs contienen "ProcessChat: model=gpt-4o"
- Si hay error, logs contienen "ProcessChat ERROR"

## Notas
- Usar package `log` stdlib (sin externe dependencies)
- Logs van a stdout (docker logs captura)
- No loguear contenido sensible (prompts/respuestas)
