# HU-056: Alinear IDs de proveedores en config.yaml con buildAdapters()

## Resumen
config.yaml usa IDs que buildAdapters() no entiende (google-gemini, local-ollama, openrouter, aihubmix). Normalizar para que coincidan.

## Descripción Técnica

La función `buildAdapters()` crea adapters con estas claves:
- `"openai"` ← config debe usar `id: openai`
- `"anthropic"` ← config debe usar `id: anthropic`
- `"google"` ← config debe usar `id: google` (no `google-gemini`)
- `"local"` ← config debe usar `id: local` (no `local-ollama`)
- `"omniroute"` ← config debe usar `id: omniroute`
- `"aihubmix"` ← config debe usar `id: aihubmix` ✓ (ya correcto)

## Acceptance Criteria

```gherkin
Given: config.yaml con IDs normalizados
When: Gateway startup
Then: no hay WARNING "sin adapter para proveedor X"
And: registry carga 5 modelos (1 por proveedor)
And: logs muestran: "registry: 5 modelos cargados desde config.yaml"
```

## Cambios en src/config.yaml

| Cambiar | A |
|---|---|
| `id: google-gemini` | `id: google` |
| `id: local-ollama` | `id: local` |
| Remover: `openrouter` | (sin adapter implementado) |

### Archivo actualizado (parcial)
```yaml
providers:
  - id: openai      # ✓ OK
  - id: anthropic   # ✓ OK
  - id: local       # ← cambio: era local-ollama
  - id: google      # ← cambio: era google-gemini
  - id: aihubmix    # ✓ OK

# NO incluir: openrouter (sin adapter)
```

## Testing

```bash
# Después del cambio
docker-compose down && docker-compose up -d && sleep 3

# Verificar sin warnings
docker logs api-llm-gateway | grep WARNING
# Esperado: sin línea "sin adapter para proveedor"

# Verificar conteo
docker logs api-llm-gateway | grep "modelos cargados"
# Esperado: "registry: 5 modelos cargados desde config.yaml"
```

## Criterio Pase
- ✓ No hay warnings de "sin adapter para proveedor"
- ✓ Registry carga 5 modelos
- ✓ Todos los IDs en config.yaml tienen adapter en buildAdapters()
